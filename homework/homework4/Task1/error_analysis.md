# Task 1: Validation Error Analysis

## 1. Selected slice and rationale

**Slice:** validation tickets that are really Technical Support but were sent to IT Support, plus the reverse (IT Support sent to Technical Support).

I picked it from the Homework 3 confusion matrix. The model got 1,782 of the 3,755 validation tickets right (47.5%), so there are 1,973 errors to choose from.

Technical Support sent to IT Support is the biggest single error in the matrix (158 tickets). The reverse adds 102 more, so this slice has 260 errors, about 13% of all errors. These are also two of the biggest departments. Technical Support has 1,095 validation tickets and the model finds only 44.7% of them (490). Only 54.9% of what it sends to Technical Support really belongs there. IT Support has 449 tickets, recall of 42.8% and precision of 37.0%, the lowest precision of the four biggest departments. A wrongly routed ticket sits in the wrong queue until someone moves it, so mistakes between big queues create the most extra work.

**How the tickets were picked:** I sorted the 260 errors by `ticket_id` and took 40 with `random_state=42` (`analyze_errors.py`, section 5). Running it again gives the same 40.

I also looked at the training split to see whether the two departments sound different. They mostly don't. "update" is in 30% of tickets in both, "restart" in 31% vs 29%, "security" in 16% vs 15%, and "access" in 14% vs 15% (Technical Support vs IT Support). The words that do differ are rare. Technical Support uses "api" a bit more (5.8% vs 3.6%) and "crash" (8.6% vs 6.6%). IT Support uses "enhance" (17% vs 9%) and "improve" (13% vs 8%) more.

## 2. How each ticket was judged

For each ticket I read the text, the model's scores, the margin (the predicted department's score minus the true department's score), and which words pushed the model toward each department. Then I asked which department the ticket belongs to, using a list of typical problems for each one. The list is general support-team knowledge, not something from the dataset, so the dataset may not follow it.

For this list, Technical Support means problems with a product: bugs, crashes, slow performance, data not syncing, API and integration failures, and trouble after an update. IT Support means a company's own systems: logins and access, networks and VPN, malware and breaches, firewalls and security setup, servers, databases and cloud setup.

## 3. Failure categories

| Category | Meaning |
|---|---|
| A. Mixed signals | The text does not point clearly to one department: it fits both, or it is too vague to tell. |
| B. Clear ticket, model misled | The list points to the true label, but the model picked the other department. |
| C. Label conflicts with list | The list points to the predicted department, not the true label. |

## 5. Failure categories: counts, impact, addressability

The 40 tickets are a random sample of the 260 errors, so the "estimated in slice" column just scales each count up to 260. Treat it as a rough guess. With only 40 tickets, each share could be off by several points.

| Category | Count (of 40) | Estimated in slice (of 260) | Likely impact on the classifier | Addressable by model or preprocessing? |
|---|---|---|---|---|
| A. Mixed signals | 11 | about 72 | The smallest group. Many have tiny margins, so the model is close to a coin flip between the two departments. A different model probably won't change this much. | No. The text has almost no signal that separates the two departments (section 1). Sending low-margin predictions to a person would help, but that changes how the app uses the model, not the model. |
| B. Clear ticket, model misled | 16 | about 104 | The biggest group, and the only one where I could point to a clear cause. Even if all of these were fixed, accuracy would go up by about 2.8 points at most (104 of 3,755). | Yes, in principle. ## 6. Limitations

- The department list is general knowledge, not the dataset's own rules. Category C means "disagrees with the list", not "mislabeled". Security and breach words show up about equally in both departments in training, so the dataset may label these tickets by some other pattern.
- For almost every ticket I checked which words pushed the baseline model's score toward each department (the model's TF-IDF and logistic regression weights for that ticket). The explanations are my reading of those words, not proof of how the model reasons.
- 40 tickets is a sample, so the shares for the whole slice are estimates.
- I only used validation data and the training split. The test split was not touched.
